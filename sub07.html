LUMÉ

스킨케어 브랜드 LUMÉ를 직접 만들고, 컬러·타이포 토큰부터 장바구니·결제·주문 내역까지 Next.js로 구현한 쇼핑몰입니다.

Duration: 2026.08 (집중작업 6일)
Role: UI/UX Design, Web Publishing, Frontend 100%
Tool: ChatGPT, Gemini, Claude Code
Tech Stack: Next.js 16 (App Router), React 19, TypeScript, CSS Modules, Zustand
Pages: Main, Category, Line, Product, Cart, Checkout, Login, My Page

Problem

한샘 리디자인이 이미 있는 사이트의 정보를 다시 정리하는 작업이었다면, LUMÉ는 브랜드부터 직접 만든 사이트입니다. 비교할 기존 화면이 없어서 컬러·타이포 토큰을 먼저 정하고, 화면은 그 토큰 안에서 만들었습니다. 기초 스킨케어는 제품을 하나씩 사기보다 순서대로 이어 쓰는 경우가 많아, 상품을 '라인'과 '루틴 순서'로 묶는 데이터 구조를 중심에 두었습니다. 상품 탐색부터 로그인·결제·주문 내역 확인까지 한 흐름으로 써볼 수 있게 만드는 것이 목표였습니다. 결제는 실제 연동 없이 주문 완료까지만 동작합니다.

Main

히어로 이미지는 오른쪽에 제품이, 왼쪽에 거울과 커튼 여백이 있습니다. 카피가 놓이는 왼쪽에만 배경색 그러데이션(스크림)을 깔고, 제품 쪽은 그대로 두었습니다. Editor's Pick은 판매 데이터가 없는 데모라 '베스트셀러' 대신 큐레이션으로 표기했습니다. 라인마다 몇 개씩 뽑으면 라인이 늘 때 메인도 같이 길어져서, 상품에 featured 표시를 직접 달아 6개를 골랐습니다. New Arrivals는 출시일(releasedAt) 최신순 4개로 자동 구성됩니다.

Category & Line

카테고리 배너는 메인 카테고리 타일과 같은 이미지를 가로로 잘라 다시 썼습니다. '라인별/제품별 보기' 토글은 라인이 있는 카테고리에서만 보이고, 제품별 필터 칩은 그 카테고리에 실제로 있는 제품 유형만으로 만들어집니다. 보기 상태는 URL 쿼리에 담겨 새로고침해도 유지됩니다. 라인 페이지는 라인 전용 이미지가 없어서, 배너 대신 몇 단계 루틴인지와 라인 이름·소개만 둔 텍스트 히어로로 구성했습니다.

01

디자인 토큰 기반 CSS 설계

  • 팔레트 블록 하나로 사이트 전체 컬러 교체
    globals.css의 :root에 기본 컬러 토큰 6개(base·sub·point·dark·text-mid·text-muted)를 두었습니다. 이 블록만 바꾸면 사이트 전체 색이 바뀌는 구조이고, 대체 팔레트(Soft Beige-gray)는 같은 자리에 주석으로 남겨 두었습니다. 다만 대체 팔레트는 지금 비율 그대로 쓰면 일부 텍스트 대비가 4.5:1에 못 미쳐, 바꿔 쓰려면 조정이 필요합니다.
  • 파생 색은 hex 추가 없이 color-mix()로 계산
    구분선, 서브 배경, 입력창 테두리, 그림자, 사진 위 그러데이션까지 파생 색은 모두 color-mix()로 기본 토큰에서 계산합니다. 컴포넌트 CSS에는 hex·rgba 값이 하나도 없어서, 팔레트를 바꾸면 파생 색도 같이 바뀝니다.
  • 반응형은 토큰 재정의로
    제목 크기, 컨테이너 여백, 섹션 간격을 토큰으로 두고 1024px·640px에서 값만 다시 정의합니다. 예를 들어 가장 큰 제목은 64 → 46 → 34px, 섹션 간격은 160 → 110 → 80px로 줄어듭니다. 컴포넌트의 미디어쿼리에서는 font-size를 다시 쓰지 않습니다.
  • CSS Modules + 공통 컨테이너
    컴포넌트 스타일은 CSS Modules로 나누고, 풀블리드 영역을 뺀 콘텐츠는 모두 1440px .container 안에 맞췄습니다. 약관처럼 읽는 페이지는 그 안에서 720px 폭으로 한 번 더 좁혔습니다.
02

모션은 CSS 우선

  • 스크롤 리빌 - JS는 클래스만, 움직임은 CSS가
    Reveal 컴포넌트는 IntersectionObserver로 화면 진입만 감지해 클래스를 붙이고, 한 번 나타나면 관찰을 끊습니다. 움직임(28px 위로, 1.2초)은 CSS transition이 맡습니다. 순차 등장은 --reveal-delay 변수로 간격만 넘깁니다(카테고리 타일 0.12초, 상품 그리드 0.08초).
  • 데스크톱 메뉴 - 상태 없이 :hover / :focus-within
    드롭다운은 JS 상태 없이 CSS로 엽니다. 트리거와 패널 사이 12px 여백을 margin이 아니라 패널의 padding-top으로 만들었습니다. padding 영역은 메뉴 요소 안에 포함되기 때문에, 마우스가 그 여백을 지나는 동안에도 hover가 끊기지 않습니다. 키보드로 포커스해도 같이 열립니다.
  • 아코디언 - grid-template-rows 0fr → 1fr
    높이를 JS로 재지 않고 grid-template-rows를 0fr에서 1fr로 바꿔 내용 높이만큼 펼칩니다. grid 항목에 바로 padding이 있으면 0fr이어도 그만큼 높이가 남아서, padding은 한 단계 안쪽 요소에 두는 규칙으로 정했습니다. 상품정보 제공고시와 모바일 드로어 메뉴에 같은 구조를 썼습니다.
  • prefers-reduced-motion 대응
    모션 감소 설정을 켠 사용자에게는 transition·animation 시간을 0.01ms로 줄이고, 스크롤 리빌 요소도 처음부터 보이게 했습니다. JS로 움직이는 브랜드 스토리 패럴랙스는 이 설정을 확인해 아예 실행하지 않습니다.
03

가독성과 정렬 디테일

  • 사진 위 글자 대비
    히어로는 카피가 있는 왼쪽에만, 브랜드 스토리는 인물이 있는 오른쪽을 두고 카피 쪽만 어둡게 스크림을 깔았습니다. 실제 화면에서 글자 뒤 픽셀을 재 보니 데스크톱 히어로 서브카피가 4.08:1, 모바일 브랜드 스토리 본문은 어두운 쪽 5% 기준 1.23:1이었습니다. 데스크톱은 사진과 스크림을 그대로 두고 서브카피 색을 진하게 바꾸고(4.08 → 8.40) 브랜드 스토리 글자의 투명도를 없앴습니다. 모바일 히어로는 전체 폭 그러데이션을 먼저 시험했지만 제품 부분 대비가 5.54에서 1.60으로 떨어져 제품이 흐려졌고, 글자가 놓인 띠에만 세로 그러데이션을 깔았습니다. 지금은 390·768·1024·1440px 네 폭 모두 글자 뒤 어두운 쪽 5% 기준으로 4.5:1을 넘습니다.
    히어로 스크림이 왼쪽에 몰려 있어 투명 헤더 오른쪽 메뉴(Menu·Login·Cart)는 사진 위에 그대로 놓였습니다. 그래서 헤더에 따로 얇은 스크림을 두고, 스크롤하면 사라지게 했습니다.
  • 통화 기호와 아이콘의 정렬
    처음에는 버튼 화살표를 "→" 문자로 넣었는데, 폰트마다 굵기와 기준선이 달라 정렬이 어긋났습니다. 화살표는 SVG로 바꾸고, 아이콘은 모두 채우기 없는 1.4px 선·24 viewBox·currentColor로 통일했습니다. 가격의 ₩ 기호도 숫자와 높이가 달라, 기호와 숫자를 각각 span으로 나눠 세로 가운데로 맞췄습니다.
  • 반복 카드의 높이 정렬
    좁은 자리에 쓰는 compact 카드는 상품명이 두 줄로 넘어가면 카드마다 높이가 달라져, 상품명을 한 줄 말줄임으로 처리했습니다. 할인율도 가격 옆에 두면 폭에 따라 줄이 바뀌어서 이미지 왼쪽 위 배지로 옮겼습니다. 카드를 새로 만들지 않고 ProductCard에 compact 옵션을 더해 장바구니 모달과 추천 상품 두 곳에서 씁니다.
04

접근성과 사용성

  • 모바일 드로어
    점검해 보니 Esc로 닫을 때는 포커스가 햄버거 버튼으로 돌아가지 않았고, 닫힌 드로어는 화면 밖으로 밀려나 있을 뿐이라 Tab으로 그 안의 요소 8개(닫기 버튼, 카테고리 3개, 전체 보기, 라인 링크 3개)에 들어갈 수 있었습니다. 닫는 경로를 하나로 묶어 어느 방법으로 닫아도 포커스가 돌아가게 하고, 닫힌 드로어는 inert로 막아 Tab이 닿는 요소를 0개로 만들었습니다(390·1440px에서 확인). 열려 있는 동안은 배경 스크롤을 잠그고 Tab 이동이 드로어 안에서만 돕니다. 모바일 헤더 아이콘 3개는 모두 44×44px로 누르는 영역을 맞췄습니다.
  • 위시리스트 버튼의 포커스 처리
    카드 위 위시리스트 버튼은 카드에 hover하거나 카드 안에 포커스가 있을 때 보입니다. 마우스로 누른 뒤 포커스가 버튼에 남아 있으면 마우스가 카드를 벗어나도 버튼이 계속 보여서, 클릭 직후 blur 처리했습니다. 키보드로 이동할 때의 포커스 표시는 그대로 둡니다.
  • 결제 버튼을 disabled로 막지 않음
    disabled로 막아 두면 왜 안 눌리는지 알 수 없습니다. 결제 버튼은 항상 누를 수 있게 두고, 누르는 시점에 입력 칸 4개를 순서대로 확인해 첫 번째로 빠진 칸으로 포커스와 스크롤을 옮깁니다. 빠진 항목은 버튼 바로 위에 한 번에 모아 보여줍니다.
01

라인 레지스트리 중심의 데이터 설계

  • 라인 하나를 추가하면 사이트 전체가 따라옴
    처음에는 라인을 추가할 때 상품 목록과 상세 조회 함수에도 따로 분기를 넣어야 했고, 같은 코드 블록이 라인 수만큼 반복됐습니다. 라인 정의 하나에서 라인 레지스트리, 상품 목록, 상세 데이터가 모두 만들어지도록 정리해(products.ts 953 → 882줄), 라인 하나를 추가하면 헤더의 라인 메뉴, 카테고리·라인 페이지, 상품 상세, 장바구니 안내가 모두 따라오게 했습니다. 리팩터 전후로 상품 26개의 상세, 라인·카테고리 페이지, 추천 결과, Editor's Pick, New Arrivals를 JSON으로 뽑아 비교해, 결과가 바이트 단위까지 같은 것을 확인하고 동작 변경은 다음 커밋으로 나눴습니다.
  • productIds = 루틴 순서
    라인의 productIds 배열 순서를 스킨케어 루틴 순서로 정했습니다. 라인 페이지의 상품 정렬, 장바구니의 다음 단계 안내, 상세페이지의 추천 순서가 모두 이 배열 하나를 기준으로 동작합니다.
  • 루틴 안내는 방금 담은 라인 기준으로
    처음 구현은 라인 순서상 첫 라인에서 아직 담지 않은 첫 단계를 골라, 세럼만 담아도 1단계 클렌징 밤을 권했습니다. 지금은 가장 최근에 담은 상품의 라인에서, 담은 단계 다음에 오는 상품 중 아직 없는 것을 권합니다(세럼만 → 아이 크림, 토너 + 나이트 크림 → 나이트 오일). 뒤쪽 단계를 모두 담았으면 앞쪽에서 빠진 단계를 권합니다. 안내 문구도 '{상품명}이 아직 장바구니에 없어요'에서 '루틴의 다음 단계, {상품명}도 함께 담아 보세요'로 바꿨습니다. 앞 문구는 Toner·Essence처럼 모음으로 끝나는 이름 뒤에서 조사가 틀렸습니다.
    같은 화면의 '다른 라인' 섹션은 첫 번째 라인만 빼고 있어서, 이미 담은 라인이 다시 추천됐습니다. 지금은 담긴 라인을 모두 빼고 남는 라인만 보여주고, 남는 라인이 없으면 섹션을 그리지 않습니다.
  • 이름이 겹치는 기준으로는 추천하지 않음
    "Toner", "Essence" 같은 제품 유형은 라인마다 똑같이 있어서, 이 기준으로 추천하면 다른 라인의 같은 단계 상품이 섞여 나옵니다. 추천은 라인 기준으로만 고르고, 라인이 없는 바디·헤어 상품만 상위 카테고리(categorySlug)로 찾습니다.
  • 잘못된 주소와 할인율 표시
    라인 페이지는 그 라인이 주소의 카테고리에 실제로 속하는지 확인해, 다른 카테고리의 라인 id로 들어오면 404를 보여줍니다. 할인율은 반올림하면 실제보다 크게 보일 수 있어 내림으로 계산합니다. 예를 들어 34,000원 → 29,000원은 14.7% 할인이라, 반올림하면 15%지만 14%로 표시합니다.
02

목적별로 분리한 Zustand 스토어

  • 장바구니·위시리스트·주문·결제수단 4개 스토어
    성격이 다른 상태라 스토어를 4개로 나눴고, 모두 persist로 localStorage에 저장해 새로고침해도 남습니다. 장바구니 최대 수량 99는 cartStore의 MAX_QUANTITY 상수 하나로 두고, 수량 Stepper도 이 값을 가져다 씁니다.
  • 주문은 그 시점 그대로 저장
    주문 내역에는 결제 카드를 참조로 두지 않고, 주문 시점의 요약 문자열("신용카드 · 1234-****-****-4231")과 상품명·가격·이미지를 복사해 저장합니다. 나중에 카드를 지우거나 상품 정보가 바뀌어도 지난 주문은 그대로 보입니다.
  • 저장 구조가 바뀔 때의 버전 관리
    개발 중에 주문 데이터에 필드를 추가하자, 이전 형태로 저장돼 있던 주문 때문에 주문 상세 페이지에서 오류가 났습니다. persist의 version을 2로 올리고, 그보다 낮은 버전의 데이터는 변환하지 않고 빈 목록으로 초기화하도록 했습니다. 반대로 카드 번호 가림 규칙을 바꿀 때는 데이터를 지우지 않았습니다. 결제수단은 v1 → v2, 주문은 v2 → v3으로 올리면서, 이미 저장된 '5678-12**-****-4231' 형식만 '5678-****-****-4231'로 바꿨습니다.
03

하이드레이션 안전 패턴

  • useSyncExternalStore 기반 useHasMounted
    장바구니 개수처럼 localStorage에서 읽는 값은 서버가 알 수 없어서, 그대로 그리면 서버 HTML과 첫 화면이 달라지는 hydration 오류가 납니다. 한샘 리디자인에서도 헤더 장바구니 개수에 이 문제가 남아 있었습니다. 서버와 첫 렌더에서는 false, 하이드레이션이 끝난 뒤에만 true를 돌려주는 useHasMounted 훅을 만들었습니다. useEffect + setState 방식은 ESLint 규칙(set-state-in-effect)에 걸려 useSyncExternalStore로 작성했습니다.
  • 배송정보 무한 렌더링 수정
    저장된 배송정보를 읽는 부분에서 무한 렌더링이 났습니다. useSyncExternalStore는 getSnapshot이 매번 새 객체를 돌려주면 값이 바뀐 것으로 보는데, JSON.parse는 내용이 같아도 매번 새 객체를 만들었습니다. 원본 문자열이 바뀌었을 때만 다시 파싱하고, 그 외에는 이전 객체를 그대로 돌려주도록 고쳤습니다.
  • 주문 상세의 첫 화면
    주문 상세처럼 localStorage에만 있는 데이터는 마운트 전에는 아무것도 그리지 않습니다. 그렇지 않으면 데이터를 읽기 전에 '주문 내역을 찾을 수 없습니다' 문구가 잠깐 보였다가 실제 내용으로 바뀝니다.
04

Server Action 로그인과 체험 동선

  • 로그인 - Server Action + httpOnly 쿠키
    "use server" 액션에서 계정을 확인한 뒤 httpOnly 쿠키(7일)에 세션을 저장합니다. 체크아웃과 마이페이지는 서버 컴포넌트에서 세션을 확인하고, 로그인하지 않았으면 /login으로 보냅니다. 처음에는 로그인 없이도 결제할 수 있었고 이름은 '데모 회원'으로 대신했지만, 결제수단을 마이페이지에 등록한 카드에서 고르도록 바꾸면서 로그인을 필수로 바꿨습니다.
  • 포트폴리오를 보는 사람을 위한 데모 설정
    회원가입 없이 바로 써볼 수 있게 데모 계정을 두고, 체크아웃의 배송정보와 동의 항목을 미리 채워 두었습니다. 실제 서비스라면 약관 동의를 미리 체크해 두면 안 된다는 점은 코드 주석으로 남겼습니다.
  • 카드 정보 처리
    결제수단을 등록할 때 유효기간은 MM/YY 형식, 1~12월, 이미 지난 달인지까지 확인합니다. 카드번호는 앞 4자리와 뒤 4자리만 남기고 가려서 저장하고, 원래 번호와 유효기간은 저장하지 않습니다. 배송지 검색은 다음 우편번호 서비스를 useDaumPostcode 훅으로 감싸 체크아웃에서 씁니다.

Design Decisions

주요 디자인 결정과 그 이유

명도 대비를 숫자로 확인했습니다

처음 정한 팔레트에서는 본문색이 배경 대비 4.4:1, 캡션색은 2.4:1이었습니다. 둘 다 WCAG AA 기준인 4.5:1에 못 미쳤습니다. 캡션색을 기준까지 진하게 하면 본문색과 거의 같아집니다. 그래서 텍스트 색은 본문색 하나로 정리하고, 위계는 글자 크기와 대문자, 자간으로 나눴습니다. 입력창 테두리는 장식용 구분선과 별도 토큰으로 두고 3:1을 맞췄습니다.

컴포넌트에는 hex 값을 쓰지 않습니다

hover 색, 그림자, 사진 위 그러데이션까지 전부 color-mix()로 기본 토큰에서 계산합니다. :root의 색 6줄만 바꾸면 사이트 전체 색이 같이 바뀝니다.

세리프는 화면마다 한 번 강조할 곳에만

두 폰트는 숫자냐 글자냐로 나누지 않았습니다. 그 화면에서 시선이 마지막에 머무는 곳인지를 기준으로 나눴습니다. 상세페이지 최종가와 장바구니 합계는 Cormorant이고, 상품 카드처럼 목록에 반복되는 가격은 Jost입니다.

이미지가 없는 상품은 병 실루엣으로

아직 이미지를 만들지 않은 바디·헤어 상품 2개에는 빈 박스 대신 CSS로 그린 병 실루엣을 넣었습니다. 배경 명도는 상품마다 4단계 중 하나로 다르게 줘서 카드가 나란히 있어도 구분됩니다. 이미지를 만들면 데이터에 경로만 추가하면 바뀝니다. 이런 상품은 메인 Editor's Pick에서 빼고 New Arrivals에만 노출합니다.

아이콘은 1.4px 선으로 통일

모든 아이콘은 채우기 없는 1.4px 선의 인라인 SVG입니다. Cormorant의 가는 획과 굵기를 맞췄습니다. 색은 currentColor를 따르기 때문에, hover 때 텍스트 색만 바꾸면 아이콘 색도 같이 바뀝니다.

루틴 안내는 한 줄로

LUMÉ의 상품은 라인 단위로 기획되어 있고, 라인 하나가 곧 사용 순서(루틴)입니다. 그래서 장바구니에 담은 상품의 다음 단계 중 아직 담지 않은 상품을 찾아, 주문 요약 아래에 이탤릭 한 줄로 알려줍니다. 배지나 팝업은 쓰지 않았습니다.

useHasMounted

서버와 첫 렌더는 false로 맞추고, 하이드레이션 이후에만 true를 반환합니다.

function subscribe() {
  return () => {};
}

export function useHasMounted(): boolean {
  return useSyncExternalStore(
    subscribe,
    () => true,
    () => false
  );
}

getMissingRoutineStep

가장 최근에 담은 상품의 라인부터, 담은 단계 다음에 빠진 단계를 찾습니다.

export function getMissingRoutineStep(
  cartProductIds: string[]
): RoutineSuggestion | undefined {
  const checked = new Set<string>();
  const notInCart = (id: string) =>
    !cartProductIds.includes(id);

  // 최근에 담은 상품의 라인부터
  for (let i = cartProductIds.length - 1; i >= 0; i--) {
    const line = productLines.find((l) =>
      l.productIds.includes(cartProductIds[i]));
    if (!line || checked.has(line.id)) continue;
    checked.add(line.id);

    const last = line.productIds.findLastIndex(
      (id) => cartProductIds.includes(id));
    const nextId = line.productIds
      .slice(last + 1).find(notInCart);
    const missingId = nextId ??
      line.productIds.slice(0, last).find(notInCart);
    if (!missingId) continue;

    const product = allProducts.find(
      (p) => p.id === missingId);
    if (product) return {
      product, line, isNextStep: nextId !== undefined,
    };
  }
  return undefined;
}

Retrospective

  • 한샘에서 정리한 기준을 처음부터 적용
    토큰 설계, 절제된 인터랙션, 하이드레이션 처리처럼 한샘 리디자인에서 시행착오를 겪은 부분을 처음부터 규칙으로 두고 시작했습니다. 한샘에서는 헤더 장바구니 개수에 hydration 문제가 남아 있었는데, LUMÉ에서는 useHasMounted로 처음부터 막았습니다. 메인부터 결제·주문 내역까지 전체 흐름을 6일 안에 만들 수 있었던 것도 기준을 미리 정해 둔 덕분이었습니다.
  • 어림한 대비와 실제 화면의 차이
    처음에는 사진 파일만 보고 글자 대비를 어림해, 데스크톱은 기준을 넘는다고 판단했습니다. 실제 렌더링 화면에서 글자 위치와 투명도까지 넣어 다시 재 보니 데스크톱 히어로 서브카피(4.08:1)와 브랜드 스토리 eyebrow(3.87:1)도 기준에 못 미쳤습니다. 한샘에서 폰트 굵기를 토큰으로만 확인했던 것과 같은 실수라, 이후로는 수치를 실제 화면에서 측정해 확인합니다.
  • 작업 기록이 커밋 하나에 묶임
    사이트 대부분을 커밋 하나(파일 125개, 약 14,500줄)로 올려서, 어떤 순서로 판단하고 고쳤는지가 기록에 남지 않았습니다. 이후 수정부터는 기능 단위로 나눠 커밋하고 있습니다.
  • 임시로 넣어 둔 바디·헤어 상품
    바디·헤어 카테고리는 카테고리 구조가 동작하는지 확인하려고 상품을 하나씩만 임시로 넣었고, 이미지도 아직 없어 병 실루엣으로 채웠습니다. 상품과 이미지를 채워 이 카테고리도 Editor's Pick에 올릴 수 있게 할 계획입니다.
  • 데모 로그인
    로그인은 데모 계정 하나로 동작하고 회원가입은 없습니다. 세션 쿠키에도 이메일과 이름이 서명 없이 그대로 들어 있어서, 쿠키를 직접 만들면 로그인 상태가 됩니다. 보는 사람이 바로 써보기에는 맞는 선택이었지만, 다음에는 서명된 세션과 실제 인증 흐름까지 붙여보고 싶습니다.
