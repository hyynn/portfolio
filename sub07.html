01

디자인 토큰 기반 CSS 설계

  • 팔레트 블록 하나로 사이트 전체 컬러 교체
    globals.css의 :root에 base·sub·point·dark·text-mid·text-muted 6개 컬러 토큰만 두고, 이 블록만 바꾸면 사이트 전체 컬러가 바뀌도록 설계했습니다. 대체 팔레트(Soft Beige-gray)도 같은 자리에 주석으로 준비해두었습니다.
  • 파생 색은 hex 추가 없이 color-mix()로 계산
    구분선, 서브 배경, 다크 배경 위 텍스트 같은 파생 색은 모두 color-mix()로 기본 토큰에서 계산합니다. hex 값을 새로 추가하지 않는 규칙을 두어, 팔레트를 교체해도 파생 색이 함께 따라옵니다.
  • 반응형은 토큰 재정의로
    타이포 크기(--fs-*), 컨테이너 여백, 섹션 간격을 토큰으로 두고 1024px·640px에서 토큰 값만 재정의합니다. 컴포넌트마다 font-size를 다시 선언하지 않아도 전체 리듬이 함께 줄어듭니다.
  • CSS Modules + 공통 컨테이너 컨벤션
    컴포넌트 스타일은 CSS Modules로 격리하고, 풀블리드 영역을 제외한 모든 콘텐츠는 1440px .container 안에 정렬했습니다. 읽기용 약관 페이지는 그 안에서 720px 컬럼으로 한 번 더 좁혔습니다.
02

모션은 CSS 우선

  • 스크롤 리빌 - JS는 클래스만, 움직임은 CSS가
    Reveal 컴포넌트는 IntersectionObserver로 진입 여부만 감지해 클래스를 붙이고, 실제 transition은 CSS가 담당합니다. 순차 등장은 --reveal-delay CSS 변수로 지연값만 넘겨 처리했습니다.
  • 데스크톱 메뉴 - 상태 없이 :hover / :focus-within
    드롭다운을 JS state 없이 CSS만으로 여닫습니다. 트리거와 패널 사이의 시각적 여백을 margin이 아닌 padding으로 만들어, 마우스가 그 여백을 지나는 동안에도 hover가 끊기지 않는 '투명한 다리' 구조로 구현했습니다. 키보드 포커스로도 동일하게 열립니다.
  • 아코디언 - grid-template-rows 0fr → 1fr
    JS로 높이를 측정하지 않고 콘텐츠 실제 높이만큼 펼쳐지게 했습니다. 패딩이 grid item에 직접 있으면 0fr이 실제로 0이 되지 않는 문제가 있어, 패딩은 안쪽 요소에 두는 규칙으로 정리했습니다. 상품정보 제공고시와 모바일 드로어 메뉴에 같은 패턴을 재사용했습니다.
  • prefers-reduced-motion 대응
    모션 감소 설정 사용자에게는 모든 transition·animation을 사실상 제거하고, 리빌 요소도 처음부터 보이도록 처리했습니다.
03

가독성과 정렬 디테일

  • 스크림은 필요한 곳에만
    히어로는 카피가 있는 좌측에만, 브랜드 스토리는 인물이 있는 우측을 살리고 카피 쪽만 어둡게 눌렀습니다. 투명 헤더의 우측 메뉴(Menu·Login·Cart)는 히어로 스크림의 보호를 받지 못해, 이미지 톤이 바뀌어도 깨지지 않도록 헤더 쪽에 별도의 얇은 스크림을 두었습니다.
  • 통화 기호와 아이콘의 정렬
    폰트마다 ₩ 기호와 숫자의 글리프 높이가 달라 baseline만으로는 어긋나 보여, 기호와 숫자를 별도 span으로 분리해 세로 중앙 정렬했습니다. 버튼 안의 "→" 같은 텍스트 글리프도 같은 이유로 SVG 아이콘으로 교체했고, 아이콘은 모두 currentColor 스트로크·1.4 두께·24 viewBox로 통일했습니다.
  • 반복 카드의 높이 정렬
    좁은 공간용 compact 카드는 상품명이 두 줄로 늘어나면 카드마다 높이가 달라져 한 줄 말줄임으로 처리하고, 할인율은 가격 옆 텍스트 대신 이미지 배지로 옮겨 줄바꿈을 막았습니다. 새 카드를 만들지 않고 같은 컴포넌트를 재사용해 시각 언어를 통일했습니다.
04

접근성과 사용성

  • 모바일 드로어
    열리면 배경 스크롤을 잠그고, Esc로 닫히며, 포커스가 드로어와 햄버거 버튼 사이로 되돌아갑니다. 모바일 헤더 아이콘 3개는 모두 44px 탭 영역을 확보했습니다.
  • 위시리스트 버튼의 포커스 처리
    클릭 후 포커스가 버튼에 남아 :focus-within이 유지되면 마우스가 카드를 벗어나도 버튼이 계속 보이는 문제가 있어 클릭 시 blur 처리했습니다. 키보드 탭 포커스 표시는 그대로 동작합니다.
  • 결제 버튼을 disabled로 막지 않음
    disabled로 조용히 막으면 "왜 안 눌리지"라는 의문만 남고 원인을 찾을 방법이 없습니다. 버튼은 항상 누를 수 있게 두고, 클릭 시점에 검증해 첫 번째 문제 필드로 포커스와 스크롤을 옮기며, 미충족 항목을 버튼 위에 한 번에 모아 보여줍니다.
01

라인 레지스트리 중심의 데이터 설계

  • 배열에 라인 하나를 추가하면 사이트 전체가 반응
    productLines 레지스트리에 라인을 추가하는 것만으로 헤더의 라인 서브메뉴, /category/[slug]와 /category/[slug]/[lineId] 페이지, 장바구니의 '루틴 완성' 안내와 '다른 라인' 섹션이 모두 동작합니다. 라인이 하나뿐이던 시점에는 '다른 라인' 섹션이 그려지지 않다가, 두 번째 라인이 추가되는 순간 자동으로 나타나도록 만들었습니다.
  • productIds = 루틴 순서
    라인의 productIds 배열 순서를 곧 스킨케어 루틴 순서로 정의했습니다. 라인 페이지 그리드 정렬, 장바구니에서 빠진 다음 단계 찾기, 상세페이지의 다음 단계 우선 추천이 모두 이 순서 하나를 기준으로 동작합니다.
  • 이름이 겹치는 축은 매칭 기준으로 쓰지 않음
    "Toner", "Essence" 같은 제품 유형(category)은 라인 간에도 겹치는 이름이라, 이걸로 추천을 매칭하면 다른 라인의 같은 단계 상품이 섞여 나옵니다. 추천은 반드시 라인 기준으로 매칭하고, 라인이 없는 Bodycare/Haircare 상품만 상위 카테고리(categorySlug)로 폴백합니다.
  • 잘못된 진입과 과장 표시 방지
    라인 페이지는 그 라인이 URL의 카테고리에 실제로 속하는지까지 검증해 다른 카테고리의 라인 id로 진입하는 것을 막습니다. 할인율은 반올림 시 실제보다 크게 표시될 수 있어 항상 내림 처리했습니다.
02

목적별로 분리한 Zustand 스토어

  • 장바구니·위시리스트·주문·결제수단 4개 스토어
    성격이 다른 상태를 하나로 합치지 않고 스토어를 분리했고, 모두 persist 미들웨어로 localStorage에 저장해 새로고침과 페이지 이동에도 유지됩니다. 장바구니 최대 수량(99)은 상수로 내보내 수량 Stepper와 같은 값을 공유합니다.
  • 주문은 시점의 스냅샷으로 저장
    주문 내역의 결제 수단은 카드 객체를 참조하지 않고 주문 시점의 요약 문자열로 저장합니다. 이후 등록 카드를 삭제해도 지난 주문 내역은 그대로 남습니다.
  • 저장 구조가 바뀔 때의 버전 관리
    주문 데이터에 필드가 추가되면서 이전 형태(v1)가 저장된 사용자는 상세페이지가 깨질 수 있었습니다. persist의 version과 migrate로 낮은 버전이면 안전하게 빈 목록으로 초기화하도록 처리했습니다.
03

하이드레이션 안전 패턴

  • useSyncExternalStore 기반 useHasMounted
    localStorage 값은 서버가 알 수 없어 그대로 렌더하면 hydration mismatch가 납니다. 서버와 클라이언트 첫 렌더는 항상 false로 맞추고 하이드레이션 이후에만 true를 반환하는 훅을 useEffect + setState 대신 useSyncExternalStore로 만들었습니다.
  • 스냅샷 참조 캐싱으로 무한 리렌더 방지
    useSyncExternalStore는 getSnapshot이 매번 새 참조를 반환하면 변경으로 판단해 무한 루프에 빠집니다. JSON.parse는 내용이 같아도 새 객체를 만들기 때문에, 원본 문자열이 실제로 바뀌었을 때만 다시 파싱하도록 캐싱했습니다.
  • 깜빡임 없는 첫 화면
    주문 상세처럼 localStorage에만 있는 데이터는 마운트 전에는 아무것도 그리지 않아, '주문을 찾을 수 없음' 문구가 잠깐 떴다가 실제 내용으로 바뀌는 깜빡임을 없앴습니다.
04

Server Action 로그인과 체험 동선

  • 로그인 - Server Action + httpOnly 쿠키
    "use server" 액션에서 계정을 확인하고 httpOnly 쿠키로 세션을 저장합니다. 체크아웃 페이지는 서버 컴포넌트에서 세션을 확인해 로그인하지 않은 사용자를 /login으로 리다이렉트합니다.
  • 포트폴리오 열람자를 위한 마찰 제거
    회원가입 없이 바로 쓸 수 있는 데모 계정을 두고, 체크아웃 배송정보와 동의 항목을 미리 채워 결제하기까지 바로 체험할 수 있게 했습니다. 실제 서비스라면 약관 동의를 기본 체크하면 안 된다는 점은 코드 주석으로 명시했습니다.
  • 카드 정보 처리
    결제수단 등록 시 MM/YY 형식, 월 범위, 만료 여부까지 검증하고, 국내 커머스 관행대로 마스킹한 번호만 저장해 카드번호 원본은 남기지 않습니다. 배송지 검색은 다음 우편번호 서비스를 훅으로 감싸 재사용했습니다.
